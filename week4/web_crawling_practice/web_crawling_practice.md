Python으로 웹 페이지 내용을 기반으로 질문에 답변하는 Web Page RAG 실습 코드를 작성한다.

파일 이름은 `web_crawling_rag_practice.py`로 가정한다.  
이 코드는 재직자 교육에서 사용할 실습용 코드이므로, 코딩 경험이 많지 않은 사람도 전체 흐름을 이해할 수 있도록 단순한 구조로 작성하고 주석을 충분히 작성한다.

## 만들고 싶은 결과물

사용자가 지정한 웹 기사 URL의 본문을 읽고, 그 내용을 검색 가능한 형태로 만든 뒤, 질문에 대해 기사 내용에 근거한 답변을 생성하는 프로그램이다.

이 프로그램은 웹 문서를 대상으로 하는 기본적인 RAG 구조를 보여주는 실습 코드이다.  
복잡한 기능보다 다음 흐름을 명확히 보여주는 것이 중요하다.

1. 웹 기사 URL에 접속한다.
2. HTML 문서에서 기사 본문에 해당하는 텍스트를 추출한다.
3. 추출된 텍스트를 검색하기 좋은 작은 단위로 나눈다.
4. 문서 조각을 임베딩해서 검색 가능한 벡터 DB를 만든다.
5. 사용자가 지정한 질문과 관련된 문서 조각을 검색한다.
6. 검색된 문서 조각들을 하나의 context로 합친다.
7. context와 질문을 LLM에 전달한다.
8. LLM이 웹 기사 내용에 근거해서 답변한다.
9. 중간 결과를 터미널에 출력하여 RAG가 어떻게 동작하는지 확인할 수 있게 한다.

## 실행 방식

터미널에서 바로 실행할 수 있는 하나의 Python 파일로 작성한다.  
웹 화면은 만들지 않는다.

사용자는 다음과 같은 방식으로 실행한다고 가정한다.

```
python web_crawling_rag_practice.py
```

## 입력

입력은 두 가지이다.

첫째, 웹 기사 URL이다.  
기본 URL은 코드 상단 설정값으로 분리한다.

```
https://www.bbc.com/korean/articles/cl4yml4l6j1o
```

둘째, 질문이다.  
기본 질문은 다음으로 한다.

```
이 기사의 주요 내용은 무엇인가요?
```

URL과 질문은 나중에 쉽게 바꿀 수 있도록 코드 상단 또는 `main()` 함수 안에서 분리한다.

## 출력

실행 중 다음 정보를 터미널에 출력한다.

- 웹 페이지 로딩 시작 메시지
- 추출된 문서 수
- 첫 번째 문서 내용 일부
- 분할된 텍스트 조각 수
- 검색된 문서 조각 수
- 검색된 문서 조각의 내용
- 검색된 문서 조각을 합친 context
- 최종 프롬프트 내용
- LLM이 생성한 답변

각 단계 사이에는 구분선을 출력해서 수강생이 실행 결과를 읽기 쉽게 한다.

구분선은 다음 문자열을 사용한다.

```
\n\n---\n\n
```

## 웹 문서 추출 방식

웹 페이지 전체를 그대로 사용하면 메뉴, 광고, 관련 기사, 푸터 등 불필요한 내용이 포함될 수 있다.  
따라서 가능하면 기사 본문 영역만 추출하도록 작성한다.

단, 웹 사이트마다 HTML 구조가 다를 수 있으므로 다음 점을 주석으로 설명한다.

- 기사 본문을 찾기 위해 HTML 태그나 class selector를 지정할 수 있다.
- 웹 사이트 구조가 바뀌면 본문 추출 결과가 비어 있을 수 있다.
- 본문이 제대로 추출되지 않으면 selector를 수정해야 한다.
- 처음에는 추출된 문서 내용을 출력해서 본문이 잘 들어왔는지 확인해야 한다.

기본 코드는 BBC 한국어 기사 본문을 대상으로 동작하도록 작성한다.  
다만 selector는 웹 페이지 구조에 따라 수정될 수 있다는 점을 주석으로 남긴다.

## 문서 분할 방식

웹 기사 본문이 길 수 있으므로, 검색하기 좋은 작은 문서 조각으로 나눈다.

문서 조각은 너무 짧으면 정보가 부족하고, 너무 길면 검색 정확도가 떨어질 수 있다는 점을 주석으로 설명한다.  
앞뒤 문맥이 완전히 끊기지 않도록 약간의 overlap을 둔다.

기본값은 다음 정도로 사용한다.

```
chunk size: 약 1000자
chunk overlap: 약 200자
```

이 값들은 실습자가 바꿔가며 결과 차이를 관찰할 수 있도록 코드에서 쉽게 수정 가능하게 한다.

## 벡터 DB 생성 방식

분할된 문서 조각을 임베딩해서 벡터 검색이 가능한 형태로 만든다.

이 예제에서는 가장 단순한 실습을 위해 벡터 DB를 로컬 파일로 저장하지 않아도 된다.  
프로그램 실행 중 메모리에서 벡터 DB를 만들고 바로 검색에 사용하면 된다.

단, 주석으로 다음 내용을 설명한다.

- 운영 환경에서는 벡터 DB를 저장해서 재사용할 수 있다.
- 이 실습에서는 흐름을 단순화하기 위해 매 실행마다 새로 만든다.

## 질문 답변 방식

질문이 들어오면 다음 흐름으로 처리한다.

1. 질문과 관련성이 높은 문서 조각을 검색한다.
2. 검색된 문서 조각 수를 출력한다.
3. 각 검색 문서 조각의 내용을 출력한다.
4. 검색된 문서 조각들을 하나의 context로 합친다.
5. context와 질문으로 최종 프롬프트를 만든다.
6. 최종 프롬프트를 터미널에 출력한다.
7. LLM 답변을 스트리밍 방식으로 출력한다.

답변 생성 프롬프트에는 다음 규칙을 포함한다.

- 주어진 context를 기반으로 질문에 답변한다.
- context에 없는 내용은 추측하지 않는다.
- 답변은 한국어로 작성한다.
- 질문과 관련된 내용만 답변한다.

## 사용할 로컬 모델 환경

로컬 PC에서 실행 가능한 LLM을 사용한다.  
생성용 모델과 임베딩용 모델은 분리해서 사용할 수 있도록 작성한다.

코드 상단에 다음 설정값을 둘 수 있게 한다.

```
EMBEDDING_MODEL = "nomic-embed-text"
LLM_MODEL = "llama3.1"
```

모델명은 코드 중간에 직접 박아 넣지 말고 상수로 관리한다.  
로컬 모델 서버 주소도 코드 상단에서 수정할 수 있도록 설정값으로 분리한다.

## 코드 구조

Web Page RAG 실습이므로 너무 복잡하게 만들지 않는다.  
함수 중심으로 작성하되, 각 단계의 실행 결과가 잘 보이도록 한다.

다음 역할을 하는 함수들이 있으면 좋다.

1. 웹 페이지에서 문서 텍스트를 읽는 함수
2. 읽어온 문서가 정상적으로 추출되었는지 확인해서 출력하는 함수
3. 문서를 검색하기 좋은 작은 조각으로 나누는 함수
4. 문서 조각을 임베딩해서 벡터 DB를 만드는 함수
5. 질문과 관련된 문서 조각을 검색하는 함수
6. 검색된 문서 조각을 context로 합치는 함수
7. context와 질문으로 프롬프트를 만드는 함수
8. LLM으로 답변을 생성하는 함수
9. 전체 실행 흐름을 담당하는 `main()` 함수

## 예외 처리와 안내 메시지

다음 상황에서는 사용자가 이해할 수 있는 안내 메시지를 출력한다.

- 인터넷 연결이 없을 때
- 웹 페이지에 접근할 수 없을 때
- 기사 본문이 제대로 추출되지 않았을 때
- 분할된 문서 조각이 없을 때
- 로컬 LLM이 실행 중이 아닐 때
- 임베딩 모델이 준비되어 있지 않을 때
- 생성 모델이 준비되어 있지 않을 때
- 검색 결과가 없을 때

오류가 발생했을 때는 Python 오류만 보여주지 말고, 사용자가 무엇을 확인해야 하는지 함께 안내한다.

## 설치 안내 주석

파일 맨 위에 실행 전 준비 사항을 주석으로 넣는다.

다음 내용을 포함한다.

- 이 코드는 Web Page RAG 실습 코드라는 설명
- 전체 흐름은 웹 페이지 로드 → 기사 본문 추출 → 문서 분할 → 임베딩 → 벡터 DB 생성 → 관련 문서 검색 → context 구성 → LLM 답변 생성이라는 설명
- 인터넷 연결이 필요하다는 설명
- 웹 사이트 구조가 바뀌면 본문 추출 selector를 수정해야 할 수 있다는 설명
- 필요한 Python 패키지 설치 방법
- 로컬 LLM 실행 필요
- 임베딩 모델과 생성 모델 설치 필요
- chunk size와 chunk overlap을 바꾸면 검색 결과와 답변이 달라질 수 있다는 설명

설치 안내에는 다음 모델 준비 명령을 포함한다.

```
ollama pull nomic-embed-text
ollama pull llama3.1
```

## 중요한 작성 기준

- 교육용 코드이므로 읽기 쉬운 구조를 우선한다.
- 한 파일에서 바로 실행 가능해야 한다.
- 함수 이름은 역할을 이해하기 쉽게 작성한다.
- 각 단계가 실행될 때 현재 어떤 작업을 하는지 print 문으로 보여준다.
- 주석은 “무엇을 하는 코드인지”뿐 아니라 “왜 필요한 단계인지”도 설명한다.
- 구현에 필요한 라이브러리는 적절히 선택해서 사용하되, 초보자가 이해하기 어려운 과도한 구조는 피한다.
- 같은 기능을 하는 import가 중복되지 않도록 정리한다.
- Basic Web Page RAG 실습이므로 Multi-Query Retrieval, Context Compression, Agent 기능은 추가하지 않는다.

위 요구사항을 만족하는 `web_crawling_rag_practice.py` 전체 코드를 작성한다.
