Python으로 PDF 문서를 기반으로 질문에 답변하는 터미널 프로그램을 작성한다.

이 프로그램은 재직자 교육에서 사용할 실습용 코드이다.  
코딩 경험이 많지 않은 사람도 전체 흐름을 이해할 수 있도록 함수 단위로 나누고, 각 단계에 주석을 충분히 작성한다.

## 만들고 싶은 결과물

사용자가 PDF 문서를 준비한 뒤 질문을 입력하면, 프로그램이 PDF 안에서 질문과 관련된 내용을 찾아서 답변을 생성하는 구조이다.

단순히 질문에 바로 답하는 것이 아니라, 다음과 같은 흐름으로 동작한다.

1. PDF 문서를 읽는다.
2. 문서를 검색하기 좋은 작은 단위로 나눈다.
3. 나눈 문서 조각을 검색 가능한 형태로 저장한다.
4. 사용자가 질문을 입력한다.
5. 질문을 여러 가지 표현으로 바꾸어 검색 성능을 높인다.
6. 여러 질문으로 문서 조각을 검색한다.
7. 검색된 문서 조각 중 중복되거나 불필요한 내용을 정리한다.
8. 질문에 답하는 데 필요한 핵심 문맥만 압축한다.
9. 압축된 문맥을 근거로 최종 답변을 생성한다.

## 실행 방식

터미널에서 바로 실행할 수 있는 하나의 Python 파일로 작성한다.  
파일 이름은 `advanced_rag_practice.py`로 가정한다.

웹 화면, Streamlit, FastAPI 같은 UI는 사용하지 않는다.  
사용자는 터미널에서 질문을 입력하고, 터미널에서 답변을 확인한다.

## 입력

입력은 두 가지이다.

첫째, PDF 파일이다.  
PDF 파일은 `./document/원자력안전관리_설명자료.pdf` 위치에 있다고 가정한다.

둘째, 사용자의 질문이다.  
프로그램 실행 중 `input()`으로 질문을 입력받는다.

## 출력

프로그램 실행 중 다음 정보를 화면에 출력한다.

- PDF 문서를 새로 처리하는지, 기존에 저장된 검색용 DB를 불러오는지
- PDF에서 읽어온 페이지 수
- 검색을 위해 나눈 문서 조각 수
- 원본 질문을 바탕으로 생성한 변형 질문 목록
- 각 변형 질문으로 검색된 문서 조각 수
- 전체 검색 결과 수
- 중복 제거 후 남은 문서 조각 수
- 문맥 압축 전후의 글자 수
- 최종 답변

최종 답변은 반드시 PDF에서 찾은 내용을 근거로 작성한다.  
PDF에서 답을 찾을 수 없으면 다음 문장을 출력한다.

“주어진 정보에서 질문에 대한 정보를 찾을 수 없습니다.”

## 질문 변형 기능

사용자 질문 하나만으로 검색하면 표현이 조금 다를 때 관련 내용을 놓칠 수 있다.  
따라서 사용자의 질문을 의미가 같은 여러 질문으로 바꾼 뒤, 각각의 질문으로 검색한다.

질문 변형은 다음 관점을 포함한다.

- 정의를 묻는 형태
- 설명을 요청하는 형태
- 구체적인 내용을 묻는 형태
- 절차나 과정을 묻는 형태
- 특징이나 특성을 묻는 형태
- 목적이나 이유를 묻는 형태
- 다른 표현으로 바꾼 형태

원본 질문도 검색에 반드시 포함한다.

## 검색 결과 정리 기능

여러 질문으로 검색하면 같은 문서 조각이 반복해서 검색될 수 있다.  
따라서 검색 결과를 하나로 합친 뒤, 내용이 같은 문서 조각은 중복 제거한다.

검색된 문서 조각이 너무 많으면 최종 답변 품질이 떨어질 수 있으므로, 질문에 필요한 핵심 내용만 남기고 문맥을 압축하는 단계를 넣는다.

문맥 압축 단계에서는 다음 원칙을 지킨다.

- 질문과 관련된 정보만 남긴다.
- 중복된 내용은 제거한다.
- 원문의 의미는 바꾸지 않는다.
- 답변에 필요하지 않은 세부사항은 줄인다.

## 최종 답변 규칙

최종 답변을 생성할 때는 다음 규칙을 지킨다.

- 반드시 검색된 PDF 문맥을 근거로 답변한다.
- 문맥에 없는 내용은 추측하지 않는다.
- 질문과 관련성이 높은 내용만 답변한다.
- 답을 찾을 수 없으면 “주어진 정보에서 질문에 대한 정보를 찾을 수 없습니다.”라고 답한다.
- 기술 용어나 고유명사는 임의로 번역하지 않는다.

## 코드 구조

초보자가 이해하기 쉽도록 함수 중심으로 작성한다.  
너무 복잡한 class 구조는 사용하지 않는다.

다음 역할을 하는 함수들을 포함한다.

1. PDF를 읽고 검색용 DB를 만드는 함수
2. 기존 검색용 DB가 있으면 불러오고, 없으면 새로 만드는 함수
3. 사용자 질문을 여러 개의 변형 질문으로 만드는 함수
4. 여러 질문으로 문서를 검색하고 검색 결과를 합치는 함수
5. 중복 검색 결과를 제거하는 함수
6. 검색된 문맥을 질문 중심으로 압축하는 함수
7. 압축된 문맥을 바탕으로 최종 답변을 생성하는 함수
8. 전체 실행 흐름을 담당하는 `main()` 함수

## 저장 방식

PDF를 매번 다시 처리하면 시간이 오래 걸릴 수 있으므로, 한 번 처리한 검색용 DB는 로컬 폴더에 저장한다.  
다음 실행 때는 저장된 DB가 있으면 다시 만들지 말고 불러온다.

저장 폴더 이름은 `faiss_index`로 한다.

## 사용할 LLM 환경

로컬 PC에서 실행할 수 있는 LLM을 사용한다.  
생성용 모델과 임베딩용 모델을 분리해서 사용할 수 있도록 작성한다.

기본 모델 이름은 다음과 같이 코드 상단에서 쉽게 수정할 수 있도록 한다.

- 생성용 모델: `llama3.1`
- 임베딩용 모델: `nomic-embed-text`

모델 이름, PDF 경로, DB 저장 경로는 코드 상단의 설정값으로 분리한다.

## 예외 처리

다음 상황에 대해 초보자가 이해할 수 있는 안내 메시지를 출력한다.

- PDF 파일이 없을 때
- 로컬 LLM이 실행 중이 아닐 때
- 필요한 모델이 설치되어 있지 않을 때
- 검색 결과가 없을 때

오류가 발생했을 때는 단순히 Python 오류만 보여주지 말고, 사용자가 무엇을 확인해야 하는지 함께 안내한다.

## 중요한 작성 기준

- 교육용 코드이므로 읽기 쉬운 구조를 우선한다.
- 한 파일에서 바로 실행 가능해야 한다.
- 각 단계가 실행될 때 현재 어떤 작업을 하는지 print 문으로 보여준다.
- 함수 이름은 역할을 이해하기 쉽게 작성한다.
- 주석은 “이 코드가 왜 필요한지” 중심으로 작성한다.
- 구현에 필요한 라이브러리는 적절히 선택해서 사용하되, 너무 복잡한 구조는 피한다.

위 요구사항을 만족하는 `advanced_rag_practice.py` 전체 코드를 작성한다.
