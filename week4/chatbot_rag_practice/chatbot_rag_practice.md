Python으로 여러 PDF 문서를 업로드하고, 문서 내용에 대해 질문할 수 있는 RAG 기반 웹 실습 프로그램을 작성한다.

파일 이름은 `chatbot_rag_practice.py`로 가정한다.  
이 프로그램은 재직자 교육에서 사용할 실습용 코드이므로, 코딩 경험이 많지 않은 사람도 전체 흐름을 이해할 수 있도록 함수 단위로 작성하고 주석을 충분히 작성한다.

## 만들고 싶은 결과물

사용자가 웹 화면에서 PDF 파일을 하나 이상 업로드한 뒤, 버튼을 눌러 문서를 검색 가능한 형태로 저장하고, 이후 질문을 입력하면 PDF 내용에 근거해서 답변을 생성하는 프로그램이다.

답변만 보여주는 것이 아니라, 답변의 근거가 된 PDF 문서 조각도 함께 보여준다.  
또한 검색된 문서 조각이 PDF의 어느 페이지에서 나온 내용인지 확인할 수 있도록, 해당 PDF 페이지 이미지를 함께 보여주면 좋다.

전체 사용 흐름은 다음과 같다.

1. 사용자가 웹 화면에서 PDF 파일을 업로드한다.
2. 사용자가 “PDF 벡터 DB 생성” 버튼을 누른다.
3. 프로그램이 PDF 내용을 읽는다.
4. PDF 문서를 검색하기 좋은 작은 단위로 나눈다.
5. 문서 조각을 임베딩해서 검색용 벡터 DB로 저장한다.
6. 사용자가 질문을 입력한다.
7. 프로그램이 질문과 관련된 문서 조각을 검색한다.
8. 검색된 문서 조각을 context로 사용해 LLM 답변을 생성한다.
9. 화면에 LLM 답변을 보여준다.
10. 답변 아래에 검색된 관련 문서 조각과 해당 PDF 페이지 이미지를 함께 보여준다.

## 실행 방식

웹 기반의 간단한 실습 앱으로 작성한다.  
복잡한 백엔드 서버 구조는 필요 없고, Python 파일 하나로 실행할 수 있도록 한다.

터미널에서는 다음과 같은 방식으로 실행할 수 있도록 작성한다.

```
streamlit run chatbot_rag_practice.py
```

## 화면 구성

웹 화면에는 다음 요소가 필요하다.

1. 제목

- “PDF RAG 검색 시스템”이라는 제목을 보여준다.

2. 설명 문구

- “PDF를 업로드한 뒤, 문서 내용에 대해 질문할 수 있습니다.”라는 안내 문구를 보여준다.

3. PDF 업로드 영역

- PDF 파일을 업로드할 수 있게 한다.
- 여러 개의 PDF를 동시에 업로드할 수 있게 한다.

4. 벡터 DB 생성 버튼

- 버튼 이름은 “PDF 벡터 DB 생성”으로 한다.
- 버튼을 누르면 업로드된 PDF들을 읽고 검색용 DB를 새로 만들도록 한다.
- 기존에 만들어둔 검색용 DB가 있으면 삭제하고 새로 만들도록 한다.

5. 진행 상태 표시

- PDF 로딩 중
- 문서 분할 완료
- 임베딩 벡터 생성 중
- 벡터 DB 저장 완료
- 벡터 DB 생성 완료

이런 식으로 현재 어떤 단계가 진행 중인지 사용자가 알 수 있게 한다.  
가능하면 progress bar도 사용한다.

6. 질문 입력 영역

- 사용자가 질문을 입력할 수 있는 텍스트 입력창을 만든다.

7. 질문하기 버튼

- 버튼 이름은 “질문하기”로 한다.
- 질문이 비어 있으면 질문을 입력하라는 안내 메시지를 보여준다.
- 아직 PDF 벡터 DB가 없으면 먼저 PDF 벡터 DB를 생성하라는 안내 메시지를 보여준다.

8. 답변 출력 영역

- “LLM 답변”이라는 소제목 아래에 답변을 보여준다.

9. 검색 근거 출력 영역

- “검색된 관련 문서”라는 소제목 아래에 검색된 문서 조각들을 보여준다.
- 검색 결과는 접었다 펼 수 있는 영역으로 보여준다.
- 각 검색 결과에는 검색된 텍스트 내용과 페이지 번호를 보여준다.
- 가능하면 해당 PDF 페이지를 이미지로 변환해서 함께 보여준다.

## 입력

입력은 두 가지이다.

첫째, 사용자가 업로드하는 PDF 파일들이다.  
여러 개의 PDF를 받을 수 있어야 한다.

둘째, 사용자의 질문이다.  
웹 화면의 텍스트 입력창에서 질문을 입력받는다.

## 출력

출력은 다음과 같다.

- PDF 처리 진행 상태
- 벡터 DB 생성 완료 메시지
- 사용자 질문에 대한 LLM 답변
- 검색된 관련 문서 조각
- 각 검색 결과의 페이지 번호
- 가능하다면 해당 PDF 페이지 이미지

## 문서 처리 방식

업로드된 PDF는 임시 폴더에 저장한 뒤 처리한다.  
PDF 파일마다 문서 내용을 읽고, 각 페이지의 텍스트와 metadata를 함께 보관한다.

metadata에는 최소한 다음 정보가 포함되면 좋다.

- 원본 PDF 파일 경로
- 페이지 번호

여러 PDF에서 읽은 문서들을 하나로 모은 뒤, 검색하기 좋은 작은 문서 조각으로 나눈다.  
문서 조각은 너무 길지 않게 나누고, 문맥이 끊기지 않도록 약간의 overlap을 두면 좋다.

## 벡터 DB 저장 방식

PDF를 처리한 결과는 로컬 벡터 DB로 저장한다.  
벡터 DB 저장 경로는 코드 상단에서 쉽게 수정할 수 있도록 설정값으로 분리한다.

기본 저장 경로는 다음으로 한다.

```
VECTOR_DB_PATH = "./vector_db/faiss_vector_db"
```

사용자가 새 PDF를 업로드하고 벡터 DB 생성 버튼을 누르면, 기존 벡터 DB는 삭제하고 새로 만들도록 한다.

## PDF 페이지 이미지 표시 기능

검색된 문서 조각이 어느 PDF 페이지에서 나온 것인지 확인할 수 있도록, 해당 PDF 페이지를 이미지로 변환해서 화면에 보여주고 싶다.

이를 위해 다음 기능을 넣는다.

- PDF 페이지를 이미지 파일로 변환한다.
- 변환된 이미지는 로컬 폴더에 저장한다.
- 검색 결과의 페이지 번호에 해당하는 이미지를 화면에 보여준다.
- 이미지 저장 폴더 경로는 코드 상단 설정값으로 분리한다.

기본 이미지 저장 경로는 다음으로 한다.

```
IMAGE_OUTPUT_PATH = "./pdf_images"
```

## RAG 답변 생성 방식

질문이 들어오면 다음 흐름으로 처리한다.

1. 저장된 벡터 DB를 불러온다.
2. 사용자 질문과 관련성이 높은 문서 조각을 검색한다.
3. 관련 문서 조각은 기본적으로 3개 정도 검색한다.
4. 검색된 문서 조각의 텍스트를 하나의 context로 합친다.
5. context와 사용자 질문을 LLM에게 전달한다.
6. LLM은 context에 근거해서 답변한다.

답변은 너무 길지 않게 작성되도록 한다.  
기본적으로 5줄 이내로 간결하게 답변하도록 프롬프트를 작성한다.

## 사용할 LLM 환경

로컬 PC에서 실행 가능한 LLM을 사용한다.  
생성용 모델과 임베딩용 모델은 분리해서 사용할 수 있도록 작성한다.

코드 상단에 다음 설정값을 둘 수 있게 한다.

```
EMBEDDING_MODEL = "nomic-embed-text"
LLM_MODEL = "llama3.1"
```

나중에 모델명을 바꿔 실험할 수 있도록 모델명은 코드 중간에 직접 박아 넣지 말고 상수로 관리한다.

## 코드 구조

초보자가 이해하기 쉽도록 함수 중심으로 작성한다.  
너무 복잡한 class 구조는 사용하지 않는다.

다음 역할을 하는 함수들이 있으면 좋다.

1. 업로드된 PDF 파일을 임시 폴더에 저장하는 함수
2. PDF 파일을 페이지 단위 문서로 변환하는 함수
3. 문서를 검색하기 좋은 작은 조각으로 나누는 함수
4. 임베딩 모델을 준비하는 함수
5. 문서 조각을 벡터 DB에 저장하는 함수
6. 기존 벡터 DB를 삭제하는 함수
7. 업로드된 PDF들로 벡터 DB를 새로 만드는 함수
8. 저장된 벡터 DB에서 질문과 관련된 문서를 검색하는 함수
9. 검색된 문서를 context로 묶고 LLM 답변을 생성하는 함수
10. PDF 페이지를 이미지로 변환하는 함수
11. PDF 페이지 이미지를 화면에 표시하는 함수
12. 웹 화면의 전체 실행 흐름을 담당하는 메인 코드

## 예외 처리와 안내 메시지

다음 상황에서는 사용자가 이해할 수 있는 안내 메시지를 보여준다.

- PDF 파일을 업로드하지 않고 벡터 DB 생성 버튼을 눌렀을 때
- 질문을 입력하지 않고 질문하기 버튼을 눌렀을 때
- 벡터 DB를 생성하지 않고 질문하기 버튼을 눌렀을 때
- PDF 읽기에 실패했을 때
- 로컬 LLM 또는 임베딩 모델 호출에 실패했을 때
- 검색 결과가 없을 때
- PDF 페이지 이미지를 만들 수 없을 때

오류가 발생했을 때는 Python 오류만 보여주지 말고, 사용자가 확인해야 할 항목을 함께 안내한다.

## 설치 안내 주석

파일 맨 위에 실행 전 준비 사항을 주석으로 넣는다.

다음 내용을 포함한다.

- 이 코드는 여러 PDF를 업로드해 질문-답변을 수행하는 RAG 실습 코드라는 설명
- 실행 명령어
- 필요한 Python 패키지 설치 방법
- 로컬 LLM 실행 필요
- 임베딩 모델과 생성 모델 설치 필요
- PDF 업로드 후 벡터 DB 생성 버튼을 먼저 눌러야 한다는 설명

## 중요한 작성 기준

- 교육용 코드이므로 읽기 쉬운 구조를 우선한다.
- 한 파일에서 바로 실행 가능해야 한다.
- 함수 이름은 역할을 이해하기 쉽게 작성한다.
- 주석은 “무엇을 하는 코드인지”뿐 아니라 “왜 필요한 단계인지”도 설명한다.
- 화면에는 사용자가 현재 어떤 단계에 있는지 알 수 있도록 안내 문구를 충분히 보여준다.
- 구현에 필요한 라이브러리는 적절히 선택해서 사용하되, 초보자가 이해하기 어려운 과도한 구조는 피한다.
- 같은 기능을 하는 import가 중복되지 않도록 정리한다.

위 요구사항을 만족하는 `chatbot_rag_practice.py` 전체 코드를 작성한다.
