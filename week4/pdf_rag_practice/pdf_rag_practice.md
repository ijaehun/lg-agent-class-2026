Python으로 PDF 문서를 기반으로 질문에 답변하는 RAG 실습 코드를 작성한다.

파일 이름은 `pdf_rag_practice.py`로 가정한다.  
이 코드는 재직자 교육에서 사용할 실습용 코드이므로, 코딩 경험이 많지 않은 사람도 전체 흐름을 이해할 수 있도록 단순한 구조로 작성하고 주석을 충분히 작성한다.

## 만들고 싶은 결과물

사용자가 PDF 문서를 하나 준비한 뒤, 터미널에서 질문을 입력하면 프로그램이 PDF 내용에서 관련 문서를 찾아 답변하는 프로그램이다.

이 프로그램은 가장 기본적인 RAG 구조를 보여주는 실습 코드이다.  
복잡한 기능보다 다음 흐름을 명확히 보여주는 것이 중요하다.

1. PDF 문서를 읽는다.
2. 문서를 검색하기 좋은 작은 단위로 나눈다.
3. 문서 조각을 임베딩해서 검색 가능한 벡터 DB로 저장한다.
4. 사용자가 터미널에서 질문을 입력한다.
5. 질문과 관련된 문서 조각을 벡터 DB에서 검색한다.
6. 검색된 문서 조각을 하나의 context로 합친다.
7. context와 질문을 LLM에 전달한다.
8. LLM이 PDF 내용에 근거해서 답변한다.
9. 사용자가 “끝” 또는 “exit”를 입력하면 프로그램을 종료한다.

## 실행 방식

터미널에서 바로 실행할 수 있는 하나의 Python 파일로 작성한다.  
웹 화면은 만들지 않는다.

사용자는 다음과 같은 방식으로 실행한다고 가정한다.

```
python pdf_rag_practice.py
```

## 입력

입력은 두 가지이다.

첫째, PDF 파일이다.  
PDF 파일은 다음 경로에 있다고 가정한다.

```
./document/weather_news.pdf
```

둘째, 사용자의 질문이다.  
프로그램 실행 중 터미널에서 질문을 입력받는다.

질문 입력창에는 다음과 같이 표시한다.

```
당신:
```

사용자가 다음 중 하나를 입력하면 대화를 종료한다.

```
끝
exit
```

## 출력

실행 중 다음 정보를 터미널에 출력한다.

- 기존 벡터 DB를 불러오는지, 새로 만드는지
- PDF 문서에서 읽어온 페이지 수
- 문서를 나눈 chunk 수
- 사용자 질문과 관련해 검색된 문서 조각 수
- LLM이 생성한 답변
- 종료 시 대화 종료 메시지

답변 출력 전에는 다음 문구를 보여준다.

```
LLM이 생성한 답변:
```

## 문서 처리 방식

PDF 문서를 페이지 단위로 읽고, 각 페이지의 텍스트와 metadata를 보관한다.  
그다음 긴 문서를 검색하기 좋은 작은 문서 조각으로 나눈다.

문서 조각은 너무 길지 않게 나누되, 앞뒤 문맥이 완전히 끊기지 않도록 약간의 overlap을 둔다.

기본적으로 다음 정도의 크기를 사용할 수 있도록 한다.

```
chunk size: 약 700자
chunk overlap: 약 70자
```

단, 이 값들은 코드 상단이나 함수 안에서 쉽게 수정할 수 있도록 한다.

## 벡터 DB 저장 방식

PDF를 매번 다시 처리하면 시간이 오래 걸릴 수 있으므로, 한 번 만든 검색용 벡터 DB는 로컬 폴더에 저장한다.

벡터 DB 저장 경로는 코드 상단에서 쉽게 수정할 수 있도록 설정값으로 분리한다.

기본 저장 경로는 다음으로 한다.

```
VECTOR_DB_PATH = "./vector_db/faiss_vector_db"
```

프로그램 실행 시 이 경로에 기존 벡터 DB가 있으면 새로 만들지 말고 불러온다.  
기존 벡터 DB가 없으면 PDF를 읽어서 새로 만든다.

## 질문 답변 방식

사용자가 질문을 입력하면 다음 흐름으로 처리한다.

1. 벡터 DB에서 질문과 관련된 문서 조각을 검색한다.
2. 검색된 문서 조각 수를 출력한다.
3. 검색된 문서 조각의 텍스트를 하나의 context로 합친다.
4. context와 질문을 LLM에게 전달한다.
5. LLM이 context에 근거해서 답변한다.
6. 답변은 스트리밍 방식으로 한 글자 또는 한 덩어리씩 출력되면 좋다.

답변 생성 프롬프트에는 다음 규칙을 포함한다.

- 주어진 context를 기반으로 질문에 답변한다.
- context에 없는 내용은 추측하지 않는다.
- 답변은 한국어로 작성한다.
- 질문과 관련된 내용만 답변한다.

## 사용할 로컬 모델 환경

로컬 PC에서 실행 가능한 LLM을 사용한다.  
생성용 모델과 임베딩용 모델은 분리해서 사용할 수 있도록 작성한다.

코드 상단에 다음 설정값을 둘 수 있도록 한다.

```
EMBEDDING_MODEL = "nomic-embed-text"
LLM_MODEL = "llama3.1"
```

모델명은 코드 중간에 직접 박아 넣지 말고 상수로 관리한다.  
로컬 모델 서버 주소도 코드 상단에서 수정할 수 있도록 설정값으로 분리한다.

## 코드 구조

Basic RAG 실습이므로 너무 복잡하게 만들지 않는다.  
함수는 많지 않아도 되지만, 최소한 다음 역할은 분리한다.

1. PDF를 읽고 벡터 DB를 새로 만드는 함수
2. 기존 벡터 DB가 있으면 불러오고, 없으면 새로 만드는 로직
3. 사용자 질문을 반복해서 입력받는 대화 루프
4. 질문과 관련된 문서를 검색하는 부분
5. 검색된 context와 질문으로 답변을 생성하는 부분

가능하면 `main()` 함수를 두어 전체 실행 흐름이 잘 보이도록 작성한다.

## 예외 처리와 안내 메시지

다음 상황에서는 사용자가 이해할 수 있는 안내 메시지를 출력한다.

- PDF 파일이 없을 때
- 로컬 LLM이 실행 중이 아닐 때
- 임베딩 모델이 준비되어 있지 않을 때
- 생성 모델이 준비되어 있지 않을 때
- 벡터 DB 로드에 실패했을 때
- 검색 결과가 없을 때

오류가 발생했을 때는 Python 오류만 보여주지 말고, 사용자가 무엇을 확인해야 하는지 함께 안내한다.

## 설치 안내 주석

파일 맨 위에 실행 전 준비 사항을 주석으로 넣는다.

다음 내용을 포함한다.

- 이 코드는 Basic PDF RAG 실습 코드라는 설명
- 전체 흐름은 PDF 로드 → 문서 분할 → 임베딩 → 벡터 DB 저장 → 질문 입력 → 관련 문서 검색 → context 구성 → LLM 답변 생성이라는 설명
- PDF 파일을 `./document/weather_news.pdf` 위치에 넣어야 한다는 설명
- 필요한 Python 패키지 설치 방법
- 로컬 LLM 실행 필요
- 임베딩 모델과 생성 모델 설치 필요
- 질문 입력창에 “끝” 또는 “exit”를 입력하면 종료된다는 설명

설치 안내에는 다음 모델 준비 명령을 포함한다.

```
ollama pull nomic-embed-text
ollama pull llama3.1
```

## 중요한 작성 기준

- 교육용 코드이므로 읽기 쉬운 구조를 우선한다.
- 한 파일에서 바로 실행 가능해야 한다.
- 함수 이름은 역할을 이해하기 쉽게 작성한다.
- 각 단계가 실행될 때 현재 어떤 작업을 하는지 print 문으로 보여준다.
- 주석은 “무엇을 하는 코드인지”뿐 아니라 “왜 필요한 단계인지”도 설명한다.
- 구현에 필요한 라이브러리는 적절히 선택해서 사용하되, 초보자가 이해하기 어려운 과도한 구조는 피한다.
- 같은 기능을 하는 import가 중복되지 않도록 정리한다.
- Basic RAG 실습이므로 Multi-Query Retrieval, Context Compression, Agent 기능은 추가하지 않는다.

위 요구사항을 만족하는 `pdf_rag_practice.py` 전체 코드를 작성한다.
