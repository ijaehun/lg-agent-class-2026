## 무엇을 만들 건가

**한 줄짜리 Gemini 응답 받기** (`hello.py`) → **멀티턴 대화 챗봇** (`chat.py`).

사용 예시 (`chat.py`):
```
You: 내 이름은 영희야
Model: 반가워요, 영희님!
You: 내 이름이 뭐였지?
Model: 영희님이에요.   ← history 가 있어서 기억함
```

## 어떻게 접근하나 — 바이브 코딩 사고법

**LLM 을 호출하는 게 뭔가?** 본질은 **함수 호출 한 번**.

### 단계별 사고

**1. 내가 뭘 만들 건가?**
사용자 입력 → LLM → 응답을 받아서 보여줌.

**2. 어떤 구조?**
```
입력 (prompt) → LLM API → 응답 (text)
```
세 가지만 있으면 됨. 어떤 LLM 부를지(model), 무엇을 보낼지(contents), 응답에서 무엇을 꺼낼지(response.text).

**3. 한 번에 끝나나?**
hello.py 는 한 번. chat.py 는 **여러 턴 대화** 라 반복.

**4. 여러 턴 대화는 어떻게?**
LLM 은 직전 대화를 **기억 못 함**. 그러면 우리가 매번 **전체 대화를 다시 보내야** 함 → history 리스트에 누적.

**5. 한계는?**
history 가 길어지면 토큰 소비 늘고, 어느 한계 넘으면 LLM 이 못 받음. 실무에선 자르거나 요약 필요 (이번 주는 안 다룸).

→ 이 다섯 단계가 머리에 있으면 Copilot 한테도 정확히 시킬 수 있어요.

### (3) 망가뜨려보기 — "왜 history 가 필요한가" 직접 보기

`chat.py` 가 동작하면, **history.append 두 줄을 주석 처리** 하고 다시 실행해보세요:

```
You: 내 이름은 영희야
Model: 반가워요, 영희님!
You: 내 이름이 뭐였지?
Model: 죄송하지만 이름을 알려주신 적 없어요.   ← history 없으면 기억 못 함
```

→ 이게 **LLM 이 stateless 라는 것의 의미**. 우리 코드가 매번 history 를 다시 보내야 LLM 이 기억하는 척 할 수 있어요.

### (4) Copilot 한테 시켜보기 — 같은 챗봇 짜기

빈 파일 `my_chat.py` 만들고 Copilot 한테:

**좋은 프롬프트** (위 사고법 기반):
```
Python 으로 Gemini 멀티턴 챗봇을 짜줘.

요구사항:
- google.genai SDK 사용
- .env 파일에서 GEMINI_API_KEY 로드
- 사용자 입력 받아 LLM 응답 출력
- history 리스트에 user/model 턴 누적해서 매번 contents 로 전달
- "exit" 또는 빈 줄로 종료
- 모델은 gemini-2.5-flash
```

**나쁜 프롬프트**:
```
챗봇 짜줘
```

### (5) Copilot 답 평가하기

받은 코드를 보면서 체크리스트:

- [ ] `history` 리스트가 있는가?
- [ ] 매 턴마다 history 가 **누적** 되는가? (덮어쓰지 않고)
- [ ] `contents=history` 로 전체를 보내는가?
- [ ] role 이 `"user"` / `"model"` 형식 맞는가?
- [ ] 종료 조건이 있는가?

→ 체크리스트 통과하면 Copilot 답이 정확히 동작. 빠진 거 있으면 어떻게 추가 프롬프트 짤지 생각해보세요.
