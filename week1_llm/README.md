이번 주는 시작점 — **LLM 한 번 호출** 의 기본.

## 이번 주에 배우는 것

- `client.models.generate_content(...)` 한 줄로 Gemini 부르기
- 응답에서 텍스트 꺼내기
- LLM 은 **stateless** — 직전 대화를 기억 못 함
- **history 누적** 으로 멀티턴 대화
- **LLM 만으론 내 노트에 답할 수 없다** 는 한계 발견 → 다음 주 도구 도입의 동기

## 회차 끝나면 답할 수 있어야 하는 질문

1. LLM 한 번 호출하는 **핵심 한 줄** 은 무엇인가?
2. 같은 프롬프트에도 매번 답이 다른가? 왜?
3. LLM 이 직전 대화를 기억하나? 아니라면 멀티턴은 어떻게?
4. **LLM 한테 "내 회의록 요약해줘" 라고 물으면 어떻게 답하나? 왜?**

→ 4번이 5주짜리 강의 전체의 출발점입니다.

## 무엇을 만들 건가

## 어떻게 접근하나 — 바이브 코딩 사고법

### 단계별 사고

**1. 내가 뭘 만들 건가?**
사용자 입력 → LLM → 응답 출력.

**2. 어떤 구조?**
```
입력 (prompt) → LLM API → 응답 (text)
```
세 가지 결정만 하면 됨: 어떤 모델, 무엇을 보낼지, 응답에서 무엇을 꺼낼지.

**3. 한 번에 끝나나?**
hello.py 는 한 번. chat.py 는 여러 턴 대화 → 반복.

**4. 멀티턴은 어떻게?**
LLM 은 직전 대화를 기억 못 함. 우리가 매번 **전체 대화를 다시 보내야** 함 (history 리스트).

**5. 한계는?**
- 토큰 한계 (history 가 너무 길면 못 받음)
- **사내 정보를 모름** (이게 이번 주의 핵심 발견 — 다음 주에 해결)

### (4) 망가뜨려보기 — "왜 history 가 필요한가" 직접 보기

`history.append` 두 줄을 주석 처리하고 다시 실행:

```
You: 내 이름은 영희야
Model: 반가워요!
You: 내 이름이 뭐였지?
Model: 죄송하지만 이름을 알려주신 적 없어요.   ← history 없으면 기억 못 함
```

→ **LLM 이 stateless** 라는 본질. 우리 코드가 매번 history 를 다시 보내야 LLM 이 "기억하는 척" 가능.

### (5) Copilot 한테 시켜보기 — 같은 챗봇

빈 파일 `my_chat.py` 만들고 Copilot 에게:

**좋은 프롬프트**:
```
Python 으로 Gemini 멀티턴 챗봇을 짜줘.

요구사항:
- google.genai SDK 사용
- .env 에서 GEMINI_API_KEY 로드
- history 리스트에 user/model 턴 누적, 매번 contents 로 전체 전달
- "exit" 또는 빈 줄로 종료
- 모델: gemini-2.5-flash
```

받은 코드 평가 체크리스트:
- [ ] `history` 리스트가 있는가?
- [ ] 매 턴마다 **누적** 되는가? (덮어쓰지 않고)
- [ ] `contents=history` 로 전체를 보내는가?
- [ ] role 이 `"user"` / `"model"` 형식 맞는가?
- [ ] 종료 조건이 있는가?
